Set up your application locally

Five checkpoints

Configuration stays in your project directory. This guide does not submit commands, manifests or destinations to the server.

Create a project

From your application's directory, scaffold a local integration manifest. Choose a stable project identifier.

duress init --project my-integration

Connect the target

Edit duress.toml locally. Configure the supported managed process or staging adapter, readiness, signing references and event fixtures for your owned test application.

What stays local?

Executable commands, endpoint destinations, secret environment references and manifest paths are managed by your local configuration. The web UI accepts only registered project and scenario identifiers.

Observe business state

Configure a supported read-only observer and entity mappings. Duress needs independently observed rows to evaluate actual business effects; HTTP success alone is insufficient.

Define the contract

Select the supported invariant pack and map the entities and identities it requires. Contract and adapter versions remain attached to each investigation.

Validate, register, investigate

Run the real configuration checks before registering your application. No validation has been run by opening this guide.

duress doctor --config duress.toml
duress register --config duress.toml

Open your registered project, run read-only doctor to check observer connectivity, then choose a scenario to start a bounded investigation.

Read an investigation

Project → target
Your integration configuration and the implementation being tested.
Investigation → finding
A bounded execution and an observed business invariant violation supported by its trials.
Failure DNA
A portable reproduction artifact. Replay it, reduce it when admissible, or verify a correction against the same failure.
PASS / FAIL / INCONCLUSIVE
The declared business checks passed, failed, or lacked sufficient valid evidence. These are separate from queued, running and completed lifecycle states.
Authored fixture / historical benchmark
A proposal or retained observation with explicit provenance. Neither label implies a new hosted-model response or current execution.
