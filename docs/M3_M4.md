## Investigation

`uv run duress investigate razorpay-vulnerable --mode cached --json` executes
source-grounded authored hypotheses, not a simulated finding. Model text and
cached provenance stay visible. Citation and linkage must pass before a
hypothesis can select experiments. Confirmation requires matching check/kind/
role in an actual failed trial; PASS results can refute only when every linked
experiment ran. Structure assessment is diagnostic and does not replace trials.

Modes are `live`, `cached`, `exhaustive`. The client uses the configured
OpenAI-compatible endpoint in live mode; one malformed-output repair is allowed.
Cached mode contacts no model provider. Missing/unusable output falls back to
S1, S2, S3-rendezvous, S3-latency(200 ms), S5, S6 and S8 from the real registry.
S9 is selectable and belongs to the differential matrix, outside that seven.
The shared call/token budget is enforced before I/O and reconciled with valid
provider-reported input usage; the entire HTTP request is capped at 60 seconds.

The two interrupted E2E failures were caused by a global HTTP-client monkeypatch
that blocked both inference and legitimate localhost readiness/delivery. Saved
records showed matching parameterized IDs but zero valid trials and only
`harness_error:AssertionError`. Correcting the network guard yielded vulnerable
H1/H2 confirmed (each 5/5 matching exploration failures), naive_fix H1 refuted
(5 valid S3 passes) and H2 confirmed (5/5 S5 failures), fixed PASS with both
hypotheses refuted. Vulnerable/naive_fix each used 30 trials and produced one
signature-addressed DNA; fixed used 20 trials and produced none.

## Reduction

`uv run duress reduce <dna-id> --target razorpay-vulnerable --json` performs
bounded reverse-order greedy single-delivery removal. Preconditions require
p0 >= 0.9 and uniform original release. Static checks preserve the failure's
business roles, unchanged retained deliveries/intents and ordering, affected
concurrent groups, faults, retry policy, fixtures, seed, expectation, invariant
pack, execution semantics and rendezvous party requirements. Inadmissible
candidates run no trials. Three valid all-fail, identical-signature,
release-preserving trials are required; PASS/different signature/release rejects
and insufficient evidence remains unknown. At most ten admissible candidates
are tried. Required-evidence/pass-condition deliveries remain pinned.

Search status and operation outcome are separate. Claims are limited to
admissible single-delivery removal under the recorded predicate. No global
minimality is claimed. A proposed reduced artifact receives a new content
identity and passes preflight; independent replay revalidation must reach
p >= 0.9 with the original uniform release before it becomes primary. Otherwise
the original remains primary. The required fault-free characterization runs on the original schedule as an
empirical comparison, not as a replacement reproducer. The CLI retains
`--black-box` for compatibility and performs this experiment by default; the
HTTP API cannot disable it. Search/replay reserve at most 51 trials plus the
11-trial characterization budget; investigations reserve the full 62 before
starting reduction.

## Differential and the intentionally incomplete repair

`naive_fix` records event IDs before delegating to the existing vulnerable
handler. Repeated same-event S3 deliveries are absorbed, but distinct S5 events
for one payment still enter the real check/await/write race. S9 remains a valid
order-duplicate acknowledgement. The expected cells are:

| Scenario | vulnerable | naive_fix | fixed |
|---|---|---|---|
| S3 rendezvous | FAIL | PASS | PASS |
| S5 cross-event | FAIL | FAIL | PASS |
| S9 second payment | PASS | PASS | PASS |

`uv run duress differential --policy explore --json` runs the same scenario
specifications independently on each target and persists observed counts beside
expected verdicts. `--policy matrix` uses 20 valid trials per cell. Inconclusive
cells never count as agreement. The S5 DNA must return NOT_VERIFIED when
verify-fix compares vulnerable against naive_fix.

## Acceptance and limitations

Exact commands and observed pass/fail counts are recorded in
`IMPLEMENTATION_LOG.md`. Client behavior is tested through controlled HTTP
fixtures, cached mode has provider-network guards, and exhaustive mode runs real
managed targets. Genuine hosted inference and the plan's five-run hosted
live-versus-exhaustive evaluation have not been performed: no DURESS_LLM
credentials are available. No Ollama or model weights were used.

The original backend handoff had no M5 pages; the final integration now exposes these operations through Jinja/HTMX (see `BACKEND_HANDOFF.md`). New operations return HTTP 202 and persist progress;
M2 replay/verify remain synchronous. Background tasks are process-local, not a durable job queue. Shutdown cancels
and drains them; startup records stale queued/running work as failed instead of
resuming it. Hosted storage may be
ephemeral. Use one API worker for the in-process admission gate. See
`BACKEND_HANDOFF.md` for schemas, examples, persistence and frontend conflicts.
